# 生成層待辦（給負責生成的隊友）

這份是給你（負責**生成層**的成員）的行動清單。前半是背景與介面，你不必看過先前討論也能上手；後半是依優先級排好的待辦，以及一個你**一定會遇到的坑**與解法。

---

## 一、你負責什麼

整個系統分四層，你負責**生成層**：把推理層交來的一份 `VisualInstruction`（情緒＋prompt＋該用誰的面具），生成出**個人化的動態視覺回饋**（影片／貼圖），回覆到 LINE。

推理層（隊友已完成）會產出情緒判讀與完整視覺指令；**你只需消費那份 JSON、產出影像**，兩層以合約解耦、可各自獨立開發。

## 二、現況（哪些能跑、哪些還缺）

- ✅ `main.py` 的生成管線**能跑**（AnimateDiff + SD1.5 + person8692 LoRA，先前已產出過 GIF/貼圖）。
- ❌ `main.py` 目前的情緒決策是**寫死的 mock**（第 91–100 行手動塞「生氣」JSON），**尚未消費真實的 VisualInstruction**。
- ❌ 7 種情緒中，只有 `anger`、`neutral` 有真實素材；其餘 5 種（joy/sadness/surprise/fear/disgust）在 `assets/emotions/` 仍是**佔位色塊**。
- ❌ 動態面具是 GIF，但 **LINE 不吃 GIF**，需轉 mp4 才能送動態。

目前 LINE demo 回的是佔位色塊——**這是整個作品「完整度」最大的缺口，也就是你這層要補的**。

## 五、你一定會遇到的坑：身分 LoRA 壓抑表情

**已量測到的問題**：現有的 `person8692` 人物 LoRA 訓練資料多為中性臉，**身分訊號會壓過情緒表情**。實測用 CLIP-T 評估既有「憤怒」生成圖時，**被判成 neutral**，情緒可辨識率只有 **0.75**。也就是說，若直接照現況批次生成 7 情緒，很可能出現「joy 和 sadness 看起來差不多」。

**這不是 bug，是身分 vs 表情的取捨**，需要你調：
- **調低 LoRA 權重**（目前 `set_adapters(..., adapter_weights=[0.8])` → 試 0.5–0.7，讓表情有空間出來）
- **加強情緒 prompt 權重**（目前 `(visual_prompt:1.3)` → 可試更高，或把中性表情放進 negative prompt）
- **每情緒生成多張候選**（不同 seed），再用 CLIP-T 挑「情緒最明顯」那張（見下）
- 若仍不行：考慮以更有表情變化的資料**重訓 LoRA**，或降低訓練步數避免過擬合到中性臉

**把這個取捨寫進報告會加分**——它正是計畫書想談的「身分一致性 vs 情緒表達」技術困難點，你有實測數據佐證。

## 六、怎麼驗證你生成的素材夠好

用專案既有的一致性評估腳本，它會算**情緒可辨識率**與時序連貫等指標：
```bash
.venv\Scripts\python -m src.evaluation.evaluate_consistency
```
- **CLIP-T / 情緒可辨識率**：生成圖是否真的傳達出目標情緒（越高越好；目前 0.75，目標往上）
- **時序連貫（CLIP 幀間、warping error）**：影片是否平滑（目前 0.94–0.97，已不錯）

流程建議：每情緒生成 N 張 → 跑這個腳本評分 → 挑最高分當素材。這樣既補齊 demo，又順便產出一組「LoRA 權重 vs 情緒可辨識率」數據。
