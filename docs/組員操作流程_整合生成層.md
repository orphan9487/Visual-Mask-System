# 操作流程：把你做好的生成層接進系統、本地運作、上 LINE 測試

給負責**生成層**的你。目標：用你做好的生成層**取代**目前未完成的版本 → 在你本地端跑起來 → 在 LINE 上實測。

> **先看懂一件事（省你很多時間）**：本系統採「**離線預渲染素材庫**」設計。LINE 執行時只做「判讀情緒 → 查表 → 送圖」，**不即時生成**。因此最順、最不容易爆顯存的整合方式是：
> **用你的生成器把 7 種情緒的面具「離線先生成好」丟進 `assets/emotions/`，LINE 端幾乎不用改就會送出真面具。**
> （即時生成需要同時把 ERC 模型 + AnimateDiff 都載進 GPU，單卡 12GB 很可能 OOM——見路徑 B 的警告。）

---

## 0. 重要原則：不要蓋掉推理層／LINE 的程式

你替換的是**生成層**。推理層（`src/reasoning`）、LINE bot（`src/line_bot`）、感知層（`src/perception`）、學習迴圈（`src/learning`）都是**已驗證、能跑**的程式，**請勿整包覆蓋**。你只會動到：

- 你自己的生成程式（新增你的模組，或改 `main.py`）
- 產出素材到 `assets/emotions/`
- （只有要送動態影片時）`src/line_bot/app.py` 的**送出那一小段** + `/media` 端點一行

## 3. 你的生成器要吃的合約（VisualInstruction）

完整欄位見 [`docs/推理層-生成層_介面合約.md`](推理層-生成層_介面合約.md)。你只需用這幾個欄位：

| 欄位 | 你怎麼用 |
|---|---|
| `identity.lora_path` / `identity.lora_weight` | 載入這個 LoRA、設這個權重 |
| `positive_prompt` / `negative_prompt` | 直接餵 pipeline |
| `modality`（`video`/`sticker`） | 決定產 mp4 還是靜圖 |
| `generation_hints`（num_frames/steps/guidance_scale） | 生成參數 |

把你的生成邏輯包成一個函式，簽名建議：
```python
def generate_from_instruction(vi: dict, pipe) -> "PIL.Image | list[frames]":
    ...
```

## 4.【推薦路徑 A】離線預渲染素材庫 → LINE 幾乎零改動

### 4.1 寫一支預渲染腳本（新增 `scripts/prerender_masks.py`）

用**推理層的 VisualInstructionGenerator** 產出每種情緒的**標準 prompt**（保證與線上判讀出來的一致），再交給你的生成器：

```python
# scripts/prerender_masks.py
from pathlib import Path
from src.line_bot import config
from src.reasoning.labels import CANONICAL_EMOTIONS
from src.reasoning.visual_instruction import visual_instruction_generator as vig
# ↓↓↓ 換成你的生成模組
from your_generation_module import build_pipeline, generate_from_instruction

def main(mask_id=None, user_id=None):
    pipe = build_pipeline()                       # 你載入 AnimateDiff/SD/LoRA 的程式
    config.ASSET_DIR.mkdir(parents=True, exist_ok=True)
    for emo in CANONICAL_EMOTIONS:                # neutral/joy/sadness/anger/surprise/fear/disgust
        vi = vig.generate(emo, mask_id=mask_id, user_id=user_id).to_dict()
        media = generate_from_instruction(vi, pipe)
        # 靜圖：一律存一張 PNG（LINE 一定送得出）
        still = media[0][0] if isinstance(media, list) else media
        still.save(config.ASSET_DIR / f"{emo}.png")
        # 動態：若 modality=video，另存 mp4（見 4.3 轉檔）
        if vi["modality"] == "video":
            export_frames_to_mp4(media, config.ASSET_DIR / f"{emo}.mp4")   # 你的轉檔
        print(f"[prerender] {emo} -> {vi['modality']} done")

if __name__ == "__main__":
    main()
```
```bash
.venv\Scripts\python -m scripts.prerender_masks
```
跑完 `assets/emotions/` 就從佔位色塊變成**真面具**。

### 4.2 靜圖已自動生效
LINE bot 現在就是 `assets.media_url(emotion)` 查 `assets/emotions/<emotion>.png` 送出——**你把 PNG 換成真圖，不用改任何 LINE 程式**。

### 4.3 要送動態影片（mp4）需兩個小改動
LINE **不吃 GIF**，動態要 mp4。且目前 `/media` 端點寫死回傳 `image/png`，送 mp4 會 content-type 錯，需修：

**(a) `src/line_bot/app.py` 的 `media()` 端點**——依副檔名判斷型別：
```python
# 原本： return FileResponse(safe, media_type="image/png")
import mimetypes
mt = mimetypes.guess_type(str(safe))[0] or "application/octet-stream"
return FileResponse(safe, media_type=mt)
```

**(b) `src/line_bot/app.py` 送出那段**（在 `handle_text_event` 內，原本是
`messages = [line_api.image_message(assets.media_url(emotion))]`）——改成有 mp4 就送影片：
```python
base = config.PUBLIC_BASE_URL
mp4 = config.ASSET_DIR / f"{emotion}.mp4"
if vi["modality"] == "video" and mp4.exists():
    messages = [line_api.video_message(f"{base}/media/{emotion}.mp4",
                                       f"{base}/media/{emotion}.png")]  # 預覽圖用同名 png
else:
    messages = [line_api.image_message(assets.media_url(emotion))]
```
（`vi` 在那段程式已經有了，直接用。`video_message()` 已寫好在 `line_api.py`。）

## 5.【選用路徑 B】即時生成（每則訊息現生）

只有你堅持「每則都即時生成」才走這條。**警告**：
- **顯存**：LINE 執行時 ERC 模型（Breeze2-3B ~7GB）已常駐，再載 AnimateDiff 很可能 **OOM**（單卡 12GB）。
- **延遲**：AnimateDiff 一次數十秒～分鐘，遠超聊天即時性；`replyToken` 會過期（程式已有 push 後備，但體驗差）。

若仍要做：在 `app.py` 送出前呼叫你的 `generate_from_instruction(vi, pipe)` → 存到 `config.ASSET_DIR` → 用 `f"{PUBLIC_BASE_URL}/media/{檔名}"` 組 URL → 用 image/video message 送。**建議先用路徑 A 通過測試，B 當加分項。**

## 6. 本地運作「更新好的模型」

放模型權重（生成層屬你的領域，你自己的檔）：
```
models/8692_mask/…              # 或你新的身分 LoRA
models/motion_adapter/…         # AnimateDiff motion adapter
models/sd-vae-mse/…             # VAE
```
情緒判讀模型（Breeze2-3B）在 `.env` 設 `VMS_MOCK=0` 後首次啟動會自動從 HuggingFace 下載。

**跑真實模式**（`.env`）：
```
VMS_MOCK=0
VMS_MODEL=breeze2-3b
VMS_QUANT=4bit          # 顯存吃緊用 4bit；8GB 以上可留空(fp16，較快較準)
```

## 7. 上 LINE 測試

1. **啟動伺服器**（真實模式）：
   ```bash
   .venv\Scripts\python -m uvicorn src.line_bot.app:app --port 8000
   ```
2. **開對外 HTTPS 通道**（擇一）：
   ```bash
   ngrok http 8000        # 或 cloudflared tunnel --url http://localhost:8000
   ```
   把拿到的 https 網址填進 `.env` 的 `PUBLIC_BASE_URL`（結尾不要斜線），重啟伺服器。
3. **設 LINE webhook**：LINE Developers Console → 你的 Messaging API channel → Webhook URL 填 `https://<你的網域>/webhook` → Verify。
4. **把 bot 加進測試群組**，確認 Console 內：
   - Messaging API 分頁：`Allow bot to join group chats` 開啟
   - OA Manager → 回應設定：自動回應訊息**關閉**
5. **測試案例**（在群組打字，觀察回的面具）：

   | 測試 | 步驟 | 預期 |
   |---|---|---|
   | 語境翻轉① | 先打「你把我的資料庫刪光了」再打「真好啊」 | 回**負向**情緒面具 |
   | 語境翻轉② | 打「重置」清語境 → 「我們拿到獎學金了」→「真好啊」 | 回**喜悅**面具 |
   | 動態 vs 靜態 | 打「氣死我了」（高喚醒→video）vs「還好吧」（低→sticker） | 憤怒送 mp4、平淡送 png |
   | 多模態 | 打「沒事啊😭」 | 回**難過**（emoji 補回）|

6. **看伺服器日誌**：每則會印 `情緒 → modality → mask`；`/health` 可看模型是否載入。

## 8. 驗證面具品質（順便產報告數據）

你**一定會遇到**：person8692 身分 LoRA 是中性臉訓練的，**會壓抑表情**（實測憤怒圖被 CLIP 判成 neutral、可辨識率僅 0.75）。調法：
- 調低 `lora_weight`（0.8 → 試 0.5–0.7）
- 加強情緒 prompt 權重、或把中性表情放進 negative prompt
- 每情緒多 seed 生成候選，用一致性腳本挑最佳：
```bash
.venv\Scripts\python -m src.evaluation.evaluate_consistency
```
把「LoRA 權重 vs 情緒可辨識率」做成一組數據，**寫進報告是加分的技術困難點**。
