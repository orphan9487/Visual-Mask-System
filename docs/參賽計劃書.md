# Visual Mask System 視覺面具系統
## 全國大專校院智慧創新暨跨域整合創作競賽 — 參賽計劃書

> 一套「讀懂語境情緒、回以個人化視覺面具」的即時社交溝通輔助系統。
> 已在 LINE 真實群組完成端到端部署，並以三個資料集的量化實驗驗證核心技術。

---

## 0. 作品摘要

純文字社交聊天（LINE、Discord）缺乏語氣、表情等非語言線索，使得**反諷、關心、無奈**等情緒經常被誤讀——「真好啊」在不同語境下可能是真心道謝，也可能是氣話。**Visual Mask System** 針對此痛點，提出一套「輸入感知 → 情緒推理 → 視覺生成 → 學習迴圈」的四層系統：它不做單句情感分類，而是**結合對話語境**判讀當前訊息的真實情緒，再生成一張帶使用者個人特色的**動態視覺面具**（影片／貼圖），把文字聊天中遺失的非語言情緒線索補回去。

本作品的三項核心創新為：（1）**語境相依**的情緒判讀——同一句話因前文不同而給出不同情緒；（2）**個人化動態視覺面具**——以身分 LoRA 生成專屬臉孔，而非通用罐頭貼圖；（3）**感知—推理—生成—學習閉環**——系統會記錄使用者對回饋的更正並轉為再訓練樣本。

作品已完成可運作的端到端管線並**實際部署於 LINE**：在真實群組中，同一句「真好啊」在前文「你把我的資料庫刪光了」下被判為負向情緒、在「我們拿到獎學金了」下被判為喜悅，系統日誌的推理鏈明確引用前文，證明語境感知確實生效。核心情緒引擎另以 MELD、繁體中文單句情緒、CPED 對話三個資料集完成量化驗證，微調後加權 F1 分別提升 62%、48%、83%。

## 1. 創作動機與問題定義

### 1.1 問題背景

即時通訊已是主要社交管道，但純文字傳遞的是「內容」，遺失了面對面溝通中約六成以上的**非語言訊息**（語氣、表情、停頓）。這導致三類常見的溝通失誤：

- **反諷／言外之意被誤讀**：「你好棒棒」「真的很謝謝你喔」字面正向、底層負向。
- **情緒強度失真**：一句「還好」可能是真的沒事，也可能是壓抑的難過。
- **語境成因遺失**：讀訊息的人若沒跟上前文，容易誤判對方為何有情緒。

現有的情緒貼圖或 emoji 建議工具多半只做**單句情感分類**（正／負／中），既不看語境、也不個人化，無法真正解決上述誤讀。

### 1.2 目標使用者與情境

- **主要使用者**：習慣用文字社交、但常擔心「訊息語氣被誤會」的一般使用者；以及希望更快讀懂群組氣氛的成員。
- **核心情境**：多人群組聊天中，系統作為參與者，即時為訊息附上一張反映**當下真實情緒**的視覺面具，降低誤讀。

### 1.3 一句話核心主張

> **同一句話的情緒，由語境決定。** 情緒判讀必須「讀對前文」，視覺回饋必須「像本人」。

這正是本作品要解決、而通用單句情感分析解決不了的問題。

## 2. 系統概述與設計創新性

### 2.1 系統一句話定義

Visual Mask System 接收群組訊息，**結合對話歷史**判讀當前訊息的真實情緒與溝通意圖，再依使用者身分生成一張**個人化的動態視覺面具**作為回饋，並從使用者反應中持續學習。

### 2.2 三大設計創新

**創新一：語境相依的情緒判讀（而非單句情感分析）**
系統以一個「對話語境緩衝區（Contextual Buffer）」保存近期對話，並將其餵入情緒推理引擎。這使得系統能捕捉單看一句話絕對讀不出的情緒——**這是本作品最具辨識度的能力**。

> 實測殺手案例（LINE 真實群組）：
> - 前文「你把我的資料庫刪光了」→「真好啊」判為**負向（反諷）**
> - 前文「我們拿到獎學金了」→「真好啊」判為**喜悅**
> 兩者若用關鍵字規則都會判成中性；本系統的推理鏈明確引用前文作出區分。

**創新二：個人化動態視覺面具（而非通用罐頭貼圖）**
系統以「身分資料庫（Identity-DB）」為每位使用者綁定一組個人化生成設定（身分 LoRA + 觸發詞），生成層據此產出**帶本人臉孔特徵**的情緒面具。相較於人人相同的 emoji／官方貼圖，個人化面具更能承載「這是我的情緒表達」的社交意義。

**創新三：感知—推理—生成—學習閉環**
系統不只單向輸出，還透過「回饋監測器（Feedback Monitor）」記錄使用者對回饋的**讚同／否定／更正**，並把更正轉成監督式微調樣本，形成可持續改善的學習迴圈——讓系統越用越貼近特定社群的用語與情緒表達。

### 2.3 與現有方案的差異

| 面向 | 情緒貼圖 / emoji 建議 | **Visual Mask System** |
|---|---|---|
| 判讀單位 | 單句 | **對話語境（多句）** |
| 反諷／言外之意 | 判不出 | **可依語境判讀** |
| 視覺回饋 | 通用、人人相同 | **個人化、像本人** |
| 學習能力 | 無 | **回饋迴圈可再訓練** |
| 多模態輸入 | 僅文字 | **文字 + emoji + 貼圖融合** |

### 2.4 跨域整合特性

本作品本質上是四個領域的整合：**自然語言處理／情感運算**（對話情緒辨識與意圖推理）、**生成式視覺 AI**（擴散模型 + LoRA 個人化生成）、**人機互動與社交設計**（LINE 群組實境、多模態融合）、以及**資源受限系統工程**（單張消費級 GPU 上的量化與即時性設計）。這種跨域整合正是「智慧創新」得以落地為「可用作品」的關鍵。

## 3. 理論基礎與方法

### 3.1 情感運算與對話情緒辨識（ERC）

情緒辨識若只看單句（Sentence-level Sentiment），無法處理語境相依情緒。本作品採用**對話情緒辨識（Emotion Recognition in Conversation, ERC）** 的框架：判讀一則訊息時，同時輸入其對話歷史與說話者資訊。方法上以生成式 ERC 路線（InstructERC, Lei et al., 2023）為基礎，將情緒判讀轉為指令式生成任務，並約束輸出至固定情緒標籤集合以利量化評估。

### 3.2 兩階段 M-CoT 推理

參照 **Multimodal-CoT** 的兩階段推理精神：先產生「推理鏈（Rationale）」說明語境如何影響語氣、是否為反諷，再據此決定最終情緒標籤。此設計讓判讀過程**可解釋**（系統日誌能看到為何這樣判），對社交輔助情境尤其重要。

> **誠實的方法學發現**：我們實測比較「兩階段 vs 單次」，發現在 15 億參數的小模型上，兩階段推理**並未提升準確率**（CPED 持平、MELD 反而下降），但**一致地降低幻覺率（無效輸出）**。因此本作品將兩階段定位為「提升輸出可靠性」，而非「提升準確率」——這是以自有數據精確化文獻主張，而非照搬。

### 3.3 說話者行為先驗與跨語言遷移

引入「說話者行為先驗（Speaker Behavioral Prior）」描述使用者長期說話風格（對應 BiosERC / LaERC-S 的 speaker characteristics 設計），但**僅描述風格、不預設當前情緒**，避免系統性偏誤。底座採用多語言、繁中友善且支援參數高效微調（PEFT/LoRA）的模型，透過在英文對話資料集上先驗證方法、再遷移到繁中資料集，驗證工具鏈的資料集無關性。

### 3.4 文獻定位

- **InstructERC**（Lei et al., 2023, arXiv:2309.11911）：生成式 ERC、以 feeling wheel 統一標籤。
- **LaERC-S**（COLING 2025）：說話者感知的 LLM 情緒辨識。
- **SemEval-2024 Task 3**：對話情緒成因分析（本作品成因設計之依據；亦作為困難度的天花板參照）。
- **Multimodal-CoT**：兩階段「先推理鏈、後結論」的推理範式。

## 4. 系統架構與技術實作

### 4.1 四層架構

系統分為四層（架構圖見附錄 `docs/architecture.svg`）：

```
輸入感知層 → 推理層（M-CoT ERC） → 生成層（個人化面具） → 學習迴圈
   ↑                                                          │
   └──────────────── 使用者回饋 ────────────────────────────────┘
```

### 4.2 各層技術

**（一）輸入感知層**
- **對話語境緩衝區（Contextual Buffer）**：以 SQLite 持久化保存每個對話的近期歷史，重啟不失憶，並限制最大輪數控制成本。
- **多模態情緒融合**：把文字情緒與 emoji／貼圖情緒融合。判讀前先剝除 emoji 使兩模態乾淨分離；文字中性但 emoji 明確時把情緒補回（如「沒事啊😭」→ 最終判為難過），文字與 emoji 衝突時標記反諷旗標。

**（二）推理層（核心）**
- **兩階段 M-CoT 情緒引擎**：先產生推理鏈、再輸出固定標籤，並記錄解析失敗率作為「小模型幻覺率」量化指標。
- **語意意圖解碼器（Semantic Intent Decoder）**：在情緒之上再解出溝通意圖、情緒成因、對象與真誠／反諷。
- **視覺指令產生器（Visual Instruction Generator）**：推理層對生成層的**介面合約**，輸出正／負向提示詞、身分 LoRA 路徑、模態選擇（強度 ≥ 0.6 走影片，否則貼圖）等，使兩層解耦、可獨立開發。
- **身分資料庫（Identity-DB）**：使用者 → 個人化面具設定的註冊與綁定。

**（三）生成層**
- 以擴散模型（Stable Diffusion 1.5）+ 動態生成（AnimateDiff）+ 身分 LoRA，依視覺指令產生個人化情緒面具。
- **即時性設計**：由於動態生成需時，且「面具 per-user 固定、情緒僅少數類別」，系統採**離線預先渲染素材庫**策略——執行時只做「判讀 → 查表 → 送出」，達到近乎零延遲。

**（四）學習迴圈**
- **回饋監測器（Feedback Monitor）**：記錄互動、偵測使用者的讚同／否定／更正（含中文口語同義詞），並把更正匯出為監督式微調樣本，閉合「回饋 → 再訓練」迴圈。

### 4.3 關鍵設計決策（可被追問的深度）

- **為何預渲染而非即時生成？** 聊天即時性與擴散模型延遲衝突；面具固定 + 情緒類別有限使預渲染可行，把即時運算負擔留給輕量的推理層。
- **為何兩階段推理？** 換取輸出可靠性（降幻覺）與可解釋性，而非準確率（見 3.2 的誠實發現）。
- **為何量化？** 在單張 12GB 消費級 GPU（RTX 4070，桌面已佔用部分顯存）上塞入 3B／7B 模型，對應「資源受限下的可行性」。

## 5. 實作成果與驗證

本章以**真實部署**與**量化實驗**兩條線佐證作品的實用性與完整性。

### 5.1 真實 LINE 部署（端到端可運作）

系統已完成 LINE bot 部署，透過固定公開網域對外服務，webhook 驗簽、圖片回覆、群組訊息處理全部打通。實測涵蓋：語境相依情緒、emoji／貼圖多模態、意圖解碼、學習迴圈記錄、以及各種非預期訊息型態的防禦性處理。效能上，情緒引擎（Breeze2-3B, fp16）穩定約 2 秒／則。

**關鍵 demo 證據**（真實群組日誌）：同一句「真好啊」，前文「刪掉資料庫」→ 負向、前文「拿到獎學金」→ 喜悅；推理鏈明確引用前文。這是本作品**語境感知能力最直接的證明**。

### 5.2 核心情緒引擎量化驗證

以統一的 7 類情緒標籤空間、單次判讀的公平設定，比較零樣本與 LoRA 微調（可訓練參數僅約 0.28%、adapter 僅約 17MB）：

| 資料集 | 性質 | 零樣本 W-F1 | 微調後 W-F1 | 提升 | 幻覺率 |
|---|---|---|---|---|---|
| MELD | 英文對話 | 0.331 | **0.538** | +62% | 6.7% → 0% |
| 繁中單句情緒 | 繁體、單句、情緒鮮明 | 0.585 | **0.868** | +48% | 1.7% → 0% |
| CPED | 繁體、對話、需語境 | 0.189 | **0.345** | +83% | 8.3% → 0% |

> **誠實定位**：三個數字不可直接相比——繁中單句資料集本質較簡單（單句、情緒鮮明、無語境），CPED 最難（真實電視劇對話、細緻語境相依情緒），也最貼近本作品目標。CPED 分數偏低主因是僅使用部分訓練資料 + 小模型，且隨資料量單調提升（零樣本 0.189 → 30k 句 0.345），指出「在地繁中對話資料是關鍵瓶頸」。

### 5.3 語境貢獻的嚴謹消融

為排除「訓練／測試不一致」的干擾，另訓練無語境對照模型，做乾淨的 2×2 比較：

| 設定 | W-F1 |
|---|---|
| 有語境訓練 + 有語境測試 | **0.345** |
| 無語境訓練 + 無語境測試 | 0.194 |

→ **語境的純貢獻為 +0.151（+78%）**。重要結論：語境要有用，前提是**模型被訓練成會用它**——零樣本硬塞語境反而是噪音，微調後語境才轉為顯著增益。此發現解決了「語境到底有沒有用」的表面矛盾，是經得起追問的論點。

### 5.4 生成一致性評估

以參照-free 指標（CLIP-T 語意對齊、時序一致性、光流 warping、身分自一致性）評估生成面具。發現：憤怒情緒的生成常被 CLIP 判為中性——即**身分 LoRA 會壓抑情緒表情**，這是「身分一致 ↔ 情緒表達」取捨的具體證據，也是後續生成層要處理的技術困難點。

### 5.5 完整性與健壯性

- **健壯性**：推理失敗自動退回關鍵字規則、超長輸入截斷、意圖解碼容錯、壞 payload 防禦性解析——實測模擬 OOM／超長輸入均不當機。
- **持久化**：對話語境以 SQLite 儲存，重啟不失憶。
- **端到端驗證**：以行程內測試打真實端點 + 真實模型，健康檢查、語境相依情緒、多模態、意圖、學習迴圈、持久化全數通過。

### 5.6 誠實的限制與範圍

- **情緒辨識天花板**：即使英文乾淨腳本，ERC 加權 F1 學界水準約 0.60–0.72；真實群組對話更難。本作品不宣稱「準確」，而是聚焦「解決語境誤讀」這個具體問題。
- **生成層真面具為進行中**：目前端到端管線完整、可運作，情緒回饋以**預先渲染的面具素材庫**送出以確保即時性；**完全個人化的即時動態生成仍在開發中**（見 5.4 的情緒表達壓抑問題）。作品的完整度體現在「可運作的整條管線 + 真實部署」，而非單一模組的完美。

## 6. UI 與 UX 設計

### 6.1 設計原則

- **零學習成本**：使用者不需安裝 App、不需學新介面——系統就活在他們已在用的 LINE 群組裡，把 bot 當成一位會給情緒回饋的成員。
- **即時性優先**：聊天不能等；透過預渲染素材庫把回覆延遲壓到近乎即時（約 2 秒內判讀 + 查表送圖）。
- **不打斷、不喧賓奪主**：以圖片回覆附加情緒面具，不強制、不洗版。

### 6.2 對話互動流程

1. 使用者在群組發訊息（文字／貼圖）。
2. 系統結合語境判讀情緒 → 選擇模態（影片／貼圖）。
3. 回覆一張反映當下情緒的個人化面具。
4. 使用者可用自然語言表達「不對，應該是…」→ 系統記錄為更正（學習迴圈）。
   - 另提供「重置語境」等指令，方便乾淨開始新話題。

### 6.3 多模態輸入體驗

使用者常在文字裡用 emoji／貼圖把情緒「加回去」。系統把這些視為第二模態並與文字融合（見 4.2），使「沒事啊😭」這類文字與情緒不一致的訊息也能被正確理解——這正是社交聊天真實樣態下的 UX 考量。

### 6.4 LIFF 展示頁（互動式體驗入口）

作品另提供一頁可在 LINE 內開啟的 **LIFF 展示頁**（只讀）：使用者可輸入一句話與前文，即時看到系統判讀的情緒、valence、推理鏈與對應面具，並附「反諷版／真心版」一鍵示範，直觀呈現「語境如何翻轉情緒」。此頁同時展示 7 種情緒面具與學習迴圈統計，兼作評審與使用者的體驗入口。（頁面支援深色模式、行動裝置優先排版，並在非 LINE 環境下自動降級為一般網頁。）

## 7. 應用情境與推廣價值

- **日常社交聊天**：降低反諷／語氣被誤會的機率，減少不必要的衝突。
- **遠距協作／跨時區溝通**：文字為主的團隊溝通中，補回情緒線索。
- **情緒陪伴與自我覺察**：讓使用者從「系統怎麼讀我的話」回看自己的表達。
- **可延伸方向**：客服對話情緒監測、社群氣氛分析等（本作品聚焦社交輔助，其餘為未來延伸）。

推廣性上，系統寄生於既有通訊平台（LINE）、以個人化素材庫運作，部署成本低、使用者上手門檻近乎為零。

## 9. 預期效益與未來展望

- **對使用者**：減少文字社交的情緒誤讀，提升溝通品質。
- **技術面**：驗證了「語境感知 ERC + 個人化視覺生成」在單張消費級 GPU 上的可行性，並產出可重用的資料集無關訓練工具鏈與推理／生成介面合約。
