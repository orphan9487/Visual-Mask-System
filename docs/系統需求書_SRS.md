## 1. 文件介紹

### 1.1 目的
定義 Visual Mask System 的完整需求，供開發、驗證與競賽評審檢視系統範圍與完成度。

### 1.2 系統範圍
Visual Mask System 是一套寄生於 LINE 的即時社交溝通輔助系統。它**結合對話語境**判讀群組訊息的真實情緒與溝通意圖，回以帶使用者個人特色的**視覺面具**（圖片／動態），並從使用者回饋中學習。系統**不**攔截私人訊息、**不**做醫療或心理診斷、**不**取代人際溝通判斷。

### 1.3 名詞定義

| 縮寫／術語 | 說明 |
|---|---|
| ERC | Emotion Recognition in Conversation，對話情緒辨識 |
| M-CoT | Multimodal Chain-of-Thought，兩階段「先推理鏈、後結論」推理 |
| Contextual Buffer | 對話語境緩衝區，保存近期對話歷史 |
| Visual Instruction | 推理層交給生成層的視覺指令（介面合約） |
| Identity-DB | 身分資料庫，使用者 → 個人化面具設定 |
| LoRA | Low-Rank Adaptation，參數高效微調 |
| LIFF | LINE Front-end Framework，於 LINE 內開啟的網頁 |
| Valence | 情緒極性（正／負／中／曖昧） |

## 2. 系統總覽

### 2.1 產品定位
系統以 LINE bot 形式加入群組，作為一位「會給情緒視覺回饋」的成員。相較單句情感分析或通用貼圖，本系統的差異化在於**語境相依判讀**與**個人化視覺回饋**。

### 2.2 系統架構（四層）
```
輸入感知層 → 推理層（M-CoT ERC） → 生成層（個人化面具） → 學習迴圈
   ↑                                                          │
   └──────────────── 使用者回饋 ────────────────────────────────┘
```
| 層 | 主要模組 |
|---|---|
| 輸入感知層 | Contextual Buffer、多模態情緒融合（emoji／貼圖） |
| 推理層 | 兩階段 M-CoT 情緒引擎、語意意圖解碼器、視覺指令產生器、Identity-DB、模態選擇器 |
| 生成層 | 擴散模型 + LoRA 個人化面具生成、預渲染素材庫 |
| 學習迴圈 | 回饋監測器、更正 → 微調樣本匯出 |

### 2.3 使用者角色

| 角色 | 說明 | 主要需求 |
|---|---|---|
| 群組成員（一般使用者） | 在群組聊天、接收情緒面具回饋、給更正 | 即時、準確、不打擾 |
| 系統管理者／開發者 | 部署、設定模型、監看日誌與健康狀態 | 可觀測、可維護、可退回 |
| 評審／體驗者 | 透過 LIFF 展示頁互動體驗 | 直觀、可自助操作 |

### 2.4 營運環境

| 項目 | 規格 |
|---|---|
| 伺服器 | 具單張消費級 GPU 之主機（RTX 4070 12GB，桌面已佔用部分顯存） |
| 執行環境 | Python 3.12、專用 venv（torch 2.5.1+cu124 等，見 `requirements.txt`） |
| 對外連線 | 固定公開 HTTPS 網域（TLS 1.2+），供 LINE 存取 webhook 與媒體 |
| 平台 | LINE Messaging API（bot）、LIFF（展示頁） |

### 2.5 設計與實作限制

- **C-1（資源）**：模型須能在 12GB VRAM 內運作，必要時以 4-bit／8-bit 量化或 fp16 載入。
- **C-2（LINE 平台）**：bot 只能收到它參與的對話，**無法攔截他人私訊** → 情境須為「與 bot 同群組」。
- **C-3（LINE 媒體）**：自製內容只能走 image／video 訊息（自製貼圖不支援），且媒體須為公開 HTTPS 網址。
- **C-4（即時性）**：擴散模型即時生成過慢 → 以預渲染素材庫因應。

### 2.6 假設與相依
- 使用者已安裝 LINE 且將 bot 加入群組。
- 已取得對話參與者同意進行情緒分析（隱私前提）。
- 外部相依：LINE 平台可用、模型權重可載入、公開網域可達。

## 3. 功能需求

> 標號 FR-<層>-<序>。優先級 M/S/F。

### 3.1 輸入感知層

| 編號 | 需求 | 優先級 |
|---|---|---|
| FR-P-01 | 系統應接收 LINE 群組的**文字**訊息並取出內容。 | M |
| FR-P-02 | 系統應接收**貼圖**訊息並取其 keywords 作為情緒線索。 | M |
| FR-P-03 | 系統應維護每個對話的 **Contextual Buffer**，保存近期歷史（預設上限 6 輪，可設定）。 | M |
| FR-P-04 | Contextual Buffer 應**持久化**（重啟不失憶）。 | M |
| FR-P-05 | 系統應在情緒判讀前**剝除 emoji**，使文字與 emoji 兩模態乾淨分離。 | M |
| FR-P-06 | 系統應將文字情緒與 emoji／貼圖情緒**融合**：文字中性但 emoji 明確時補回情緒；兩者衝突時標記反諷旗標。 | M |
| FR-P-07 | 系統應對**不支援的訊息型態**（圖片／語音／影片等）回覆友善說明，不靜默、不當機。 | M |

### 3.2 推理層

| 編號 | 需求 | 優先級 |
|---|---|---|
| FR-R-01 | 系統應以**兩階段 M-CoT** 判讀當前訊息情緒：先產生推理鏈，再輸出固定情緒標籤。 | M |
| FR-R-02 | 情緒輸出應**約束至固定標籤集合**，非法／無法解析之輸出應記錄為幻覺並退回安全值。 | M |
| FR-R-03 | 判讀應**納入 Contextual Buffer 的對話歷史**（可經開關做消融）。 | M |
| FR-R-04 | 系統應可載入 **LoRA adapter** 以套用微調後的情緒判讀能力。 | M |
| FR-R-05 | 系統應提供**語意意圖解碼**：溝通意圖、情緒成因、對象、真誠／反諷。 | S |
| FR-R-06 | 系統應產生 **Visual Instruction**（正／負向提示詞、身分 LoRA、模態、生成提示）作為對生成層的合約。 | M |
| FR-R-07 | 系統應以 **Identity-DB** 解析使用者對應之個人化面具（優先序：明確指定 > 使用者綁定 > 預設）。 | M |
| FR-R-08 | 系統應依情緒強度做**模態選擇**（強度 ≥ 0.6 → 動態／影片，否則 → 貼圖）。 | S |

### 3.3 生成層

| 編號 | 需求 | 優先級 |
|---|---|---|
| FR-G-01 | 系統應為每個情緒類別提供可送出的**面具素材**（預渲染素材庫）。 | M |
| FR-G-02 | 系統應以公開 HTTPS 網址對外提供面具媒體，並防止路徑穿越。 | M |
| FR-G-03 | 生成層應能依 Visual Instruction 以擴散模型 + 身分 LoRA 產生**個人化情緒面具**。 | F（進行中） |
| FR-G-04 | 個人化生成應緩解「身分 LoRA 壓抑情緒表情」之問題，確保情緒可辨識。 | F（進行中） |

> 說明：目前 FR-G-01/02 已實作並運作（以素材庫確保即時性）；FR-G-03/04 為生成層進行中項目，端到端管線已具備 Visual Instruction 合約可供接入。

### 3.4 學習迴圈

| 編號 | 需求 | 優先級 |
|---|---|---|
| FR-L-01 | 系統應**記錄每次互動**（訊息、判讀情緒、模態、意圖等）。 | M |
| FR-L-02 | 系統應偵測使用者對回饋的**讚同／否定／更正**（含中文口語同義詞）。 | S |
| FR-L-03 | 系統應將**更正**匯出為監督式微調樣本（與訓練格式一致），閉合學習迴圈。 | S |

### 3.5 對外服務與展示

| 編號 | 需求 | 優先級 |
|---|---|---|
| FR-S-01 | 系統應提供 LINE **webhook** 端點，接收事件並即時回 200。 | M |
| FR-S-02 | 系統應以**圖片訊息**回覆對應情緒之面具；回覆失敗時以 push 後備。 | M |
| FR-S-03 | 系統應提供**健康檢查**端點（模式、模型狀態、缺漏設定、退回旗標）。 | M |
| FR-S-04 | 系統應支援**重置語境**指令（清空 Contextual Buffer）。 | S |
| FR-S-05 | 系統應提供 **LIFF 展示頁**：輸入句子 + 前文即時看情緒／推理鏈／面具，附一鍵示範與面具庫、學習迴圈統計；只讀、不寫入狀態。 | S |
| FR-S-06 | 系統應提供**除錯／展示端點**（單句判讀、視覺指令、意圖）供開發與展示。 | S |

## 4. 外部介面需求

### 4.1 使用者介面
- **UI-1 LINE 聊天介面**：以群組訊息與圖片回覆互動，零安裝、零學習成本。
- **UI-2 LIFF 展示頁**：行動裝置優先、支援深色模式；非 LINE 環境自動降級為一般網頁。

### 4.2 軟體介面
- **SI-1 LINE Messaging API**：webhook 接收（需 X-Line-Signature 驗簽）、reply／push 送訊、image／video message。
- **SI-2 LIFF SDK**：於 LINE 內取得使用者 profile、可選傳訊至聊天室（需 LINE Login channel）。
- **SI-3 模型後端（Backbone）**：可設定底座（Breeze2-3B／Qwen2.5 系列等），支援量化與 LoRA；封裝統一 chat 介面。

### 4.3 通訊介面
- **CI-1**：對外一律 HTTPS（TLS 1.2+）；媒體與 webhook 走公開固定網域。
- **CI-2**：webhook 事件為 JSON；系統對壞 payload 應防禦性解析並回 200，避免 LINE 反覆重送。

## 5. 非功能需求

### 5.1 效能
| 編號 | 需求 |
|---|---|
| NFR-PERF-01 | 單則訊息之情緒判讀 + 回覆應約在 **2 秒內**（Breeze2-3B fp16，暖機後）。 |
| NFR-PERF-02 | webhook 應**立即回 200**，重運算置於背景，避免逾時重送。 |
| NFR-PERF-03 | 超長輸入應**截斷**（上限 500 字）以控制延遲與資源。 |

### 5.2 可靠性與可用性
| 編號 | 需求 |
|---|---|
| NFR-REL-01 | 任何模型故障（OOM／逾時／載入失敗）應**自動退回關鍵字規則**，系統永不當機。 |
| NFR-REL-02 | 模型載入階段失敗應設定**永久退回旗標**，避免反覆重試。 |
| NFR-REL-03 | Contextual Buffer 應以 SQLite 持久化，重啟不失憶。 |
| NFR-REL-04 | 對非預期訊息型態與壞 payload 應優雅處理，不中斷服務。 |

### 5.3 安全與隱私
| 編號 | 需求 |
|---|---|
| NFR-SEC-01 | webhook 必須以原始 bytes 進行**簽章驗證**，失敗回 403。 |
| NFR-SEC-02 | 媒體服務必須**防止路徑穿越**，僅允許素材目錄下檔名。 |
| NFR-SEC-03 | 金鑰（Channel secret／access token 等）僅由環境變數／`.env` 注入，**不得寫入程式碼或版控**。 |
| NFR-SEC-04 | 使用者互動與回饋紀錄應**去識別化**，且不納入版控。 |
| NFR-SEC-05 | 情緒分析須在**取得參與者同意**之前提下進行。 |
| NFR-SEC-06 | 除錯／展示端點於正式對外時應關閉或加存取控制。 |

### 5.4 可用性（Usability）
| 編號 | 需求 |
|---|---|
| NFR-USE-01 | 使用者**零安裝**即可使用（活在既有 LINE 群組）。 |
| NFR-USE-02 | 回饋以圖片附加，**不強制、不洗版**。 |
| NFR-USE-03 | LIFF 展示頁支援行動裝置與深色模式。 |

### 5.5 資源限制
| 編號 | 需求 |
|---|---|
| NFR-RES-01 | 系統須能在 **12GB VRAM** 內運作（必要時量化）。 |
| NFR-RES-02 | 微調應採參數高效方式（LoRA，可訓練參數 < 1%），adapter 檔案小、易佈署。 |

### 5.6 可維護性
| 編號 | 需求 |
|---|---|
| NFR-MNT-01 | 訓練與推論須共用**同一組 prompt**（單一真實來源），避免分布不一致。 |
| NFR-MNT-02 | 推理層與生成層以 **Visual Instruction 合約**解耦，可獨立開發與替換。 |
| NFR-MNT-03 | 模型後端須與「用哪個模型」解耦，可切換底座而不改上層程式。 |

## 7. 使用案例

### UC-1 語境相依情緒回饋（主流程）
- **主角**：群組成員
- **前置**：bot 已在群組、模型就緒
- **流程**：
  1. 成員發送文字訊息。
  2. 系統取對話歷史 → 兩階段判讀情緒 → 多模態融合。
  3. 系統依情緒選模態、解析個人化面具、產生 Visual Instruction。
  4. 系統回覆對應情緒之面具圖片。
  5. 系統記錄本次互動。
- **例外**：模型故障 → 退回關鍵字規則仍完成回覆（NFR-REL-01）。

### UC-2 反諷／語境翻轉判讀
- 成員在「刪掉資料庫」前文後發「真好啊」→ 系統判為負向並回覆對應面具；同句在「拿到獎學金」前文後 → 判為喜悅。驗證 FR-R-03。

### UC-3 多模態情緒補回
- 成員發「沒事啊😭」→ 文字判中性、emoji 判難過 → 融合後最終難過。驗證 FR-P-06。

### UC-4 使用者更正（學習迴圈）
- 系統回饋後，成員回「不對，我是生氣」→ 系統記錄更正並匯出為微調樣本。驗證 FR-L-02/03。

### UC-5 LIFF 展示頁體驗
- 體驗者於 LINE 內開啟展示頁，輸入句子 + 前文，即時看情緒、推理鏈與面具，點「反諷版／真心版」示範語境翻轉。驗證 FR-S-05。

### UC-6 管理者監看健康狀態
- 管理者查詢健康端點，得知模式、模型是否載入、是否已退回關鍵字規則、缺漏設定。驗證 FR-S-03。
