# 照片面具管理（不使用 LoRA 訓練）

- `/chats`：只選擇可用面具、聊天對象，提供「面具管理」入口。
- `/masks`：命名、圖片上傳、1:1 裁切、預覽確認、切換與刪除。
- 舊 `/lora-training` 連結轉到 `/masks`；舊訓練 API 已移除。
- 新帳號與尚未建立面具的帳號直接進入 `/masks`，不再要求外觀 prompt 設定。

## 圖片與生成

前端可移動裁切框，四邊／四角縮放始終保持正方形。
照片置中於邊長為原照長邊兩倍的白色虛擬畫布，裁切可超出原照。
後端對 EXIF 校正後的原圖驗證整數座標、虛擬畫布界內範圍、寬等於高，且至少 256×256，並須與原照相交，再縮放為 1024×1024。
超出原照的像素填純白；直接映射至 1024px 輸出，不配置巨大的留白畫布。
留白不能補回原照片已缺失的頭髮、五官或下巴。
不是將長方形硬拉成正方形。預覽也以 contain 呈現。

新增面具提供兩種處理方式：自然中性原照、自動中性化本次上傳照片。
自動沿用舊基底已取消；同帳號、同人物的不同面具也各自使用自己的 source.png。
舊 API mode=new_identity 仍相容，但效果同 auto，不再需要以此避開舊基底。
既有 reuse_reference 草稿不會自動重寫，請刪除草稿後重新新增，以免無聲覆蓋使用者資料。
中性化仍使用原本 LivePortrait 方法，並非新的眼形修復模型；相似度門檻 0.30 僅初步工程篩檢，未做驗證校準，結果必須人工驗收。
neutral 直接使用確認基底；其他情緒只呼叫 LivePortrait。不再讀取 LoRA 權重，也不跑 SD1.5 修飾。

## 資料與刪除

新增資料保存在 `data/portrait_masks/{user_id}/{mask_id}/`，與 MySQL 帳號／聊天資料並存，不需要新增資料表。
每個使用者的 active.json 記錄目前面具；草稿不會直接用於聊天。
預覽、新增、確認、切換、刪除均檢查登入與擁有者。
刪除為 status=deleted 的封存；若刪除使用中面具，切到另一個已確認面具，沒有剩餘面具時要求新增。
原照片與歷史生成檔不刪除，因此不會破壞歷史訊息。

初次載入面具清單時，會從本人舊任務複製已上傳基底，一次匯入且不讀取權重。
舊非正方形基底以等比例補邊相容匯入，不拉伸；新上傳一律正方形裁切。
已確認的舊基底維持可用，未確認的舊基底須先驗收。封存面具不會反覆從舊任務重新匯入。

## 清理範圍

已移除舊訓練頁與其 lora_jobs.js、mask_delete.js、training_cropper.js。
研究腳本、訓練紀錄、照片與權重保留作離線研究與回復，未大範圍刪除。
舊 FaceID／LoRA 資料庫欄位保留相容，不做破壞式資料庫遷移。

## 驗證與啟動

8 項 Python 服務／API／生成路由測試通過，另有 Node 正方形裁切幾何測試與 JavaScript 語法檢查。
隔離資料的真實 LivePortrait smoke test 驗證 neutral 與 sadness 均輸出正方形。
測試不連線 MySQL、不更動真實使用者面具。

重啟 `python chat_server.py`，再開 `/masks`；若瀏覽器仍顯示舊內容，按 Ctrl+F5。
