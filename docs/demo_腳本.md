# Visual Mask System — Demo 展示腳本

目標時長 **約 5 分鐘**。核心策略：先用最有衝擊力的「語境反轉」抓住評審，再用「多模態」和「學習迴圈」堆疊深度，最後用實驗數據建立可信度。強烈建議**錄影版為主、現場為輔**（避免臨場網路/模型翻車）。

---

## ⚠️ 上場前檢查清單（務必逐項確認）

**環境**
- [ ] `.env` 設 **`VMS_MODEL=breeze2-3b`**（Breeze2 反諷判讀最好，Qwen 會失準——這是最容易忘的一步）
- [ ] `.env` 設 `VMS_MOCK=0`、`VMS_QUANT=fp16`（VRAM 夠）或 `4bit`

**demo 前置（讓現場乾淨、順暢）**
- [ ] **暖機**：demo 前先隨便發一則訊息，讓模型先載入（首則會慢 1–2 分鐘，別在評審面前等）
- [ ] **清乾淨計數**：依展示需求清除測試回饋資料，確保統計與語境全新
- [ ] **預演**：先私下把下面「語境反轉」兩段訊息跑一次，確認 Breeze2 真的給出相反情緒（若某句判讀不如預期，微調用詞後固定下來）

**關於視覺面具（誠實面對）**
- [ ] 7 情緒中部分仍是佔位圖（生成層由隊友完善中）。若 demo 當下真面具未齊，**把重點放在「情緒理解正確」**（用 debug 端點展示推理鏈），並口頭說明「動態面具由生成層產出，此處展示的是驅動生成的判讀與指令」。**有 anger 真面具可秀就秀。**

## 🎬 腳本（分鏡）

### ① 開場：問題（30 秒）
> **旁白**：「在 LINE 上打一句『喔，好啊』，可能是真心答應，也可能是不爽的敷衍。純文字丟失了語調與表情——這正是社交軟體上情緒誤解的根源。我們的系統為每則訊息**即時判讀情緒與意圖**，生成帶個人特色的視覺回饋，把缺失的情緒補回來。已實際部署在 LINE 上運行。」

*畫面*：LINE 群組畫面（bot 在群裡）。

---

### ② 核心亮點一：同一句話，語境不同，情緒相反（90 秒）★ 主打
在群組**依序**輸入：

**第一段（正面語境）**
```
我們這組專題拿到第一名了！
真好啊
```
→ 系統回覆「開心」回饋

**第二段（負面語境）**
```
你把我三天的程式碼刪掉了
真好啊
```
→ 系統回覆「厭惡 / 憤怒」回饋

> **旁白**：「注意——**完全相同的『真好啊』三個字**，只因為前一句不同，系統判讀出**相反的情緒**。純關鍵字方法對這兩句必定給出一樣的答案；我們的系統結合對話語境理解，而非只看字面。」

*加碼（展示深度）*：切到 `/debug/instruction?text=真好啊&history=你把我三天的程式碼刪掉了`，指出推理鏈**明確引用了前文**：
> 「你看，系統的推理過程有寫出『因為前文提到程式碼被刪，這句是反諷』——它是真的在推理，不是查表。」

---

### ③ 核心亮點二：emoji 補回文字漏掉的情緒（60 秒）
在群組輸入：
```
沒事啦
沒事啦😭
```
> **旁白**：「文字說『沒事啦』，字面是中性的。但配上一個哭泣 emoji，真正的情緒是**難過**。emoji 和貼圖，正是使用者在文字裡『把情緒加回去』的方式——這個常被忽略的訊號，我們的多模態感知也讀進來了。」

*畫面*：可切 `/debug/instruction?text=沒事啦😭` 指出 `text_emotion=neutral → 最終=sadness，來源=emoji`。

---

### ④ 深度：不只判斷情緒，還理解「為什麼」（45 秒）
切到 `/debug/intent?text=我的組員都不做事，超後悔跟他一組`
> **旁白**：「系統還會推斷**溝通意圖與情緒成因**——這句話的意圖是『抒發不滿』，成因是『組員不做事』。判斷『為什麼這樣說』，讓回饋能貼近真實的溝通意圖，而不只是表面情緒。」

---

### ⑤ 核心亮點三：會從使用者回饋學習（45 秒）
承接前面某次判讀，在群組輸入一句糾正：
```
不對，我其實是難過
```
> **旁白**：「如果判錯了，使用者只要糾正一句，系統就把這筆更正記錄下來，**自動轉成可以再訓練的資料**——形成學習迴圈，越用越懂你。」

*畫面*：切 `/feedback/stats`，指出 `feedback_total` 增加、`corrections_usable_for_training` 有值。

---

### ⑥ 技術實力（30 秒）
*畫面*：一張數據投影片（取自 README / 計畫書第五節）。
> **旁白**：「這些不只是 demo。我們在**真實繁體中文對話資料**上做輕量化微調，情緒辨識 F1 隨在地資料量單調提升；並以嚴謹消融**量化證明對話語境的貢獻達 +0.15**。整套系統跑在**單張消費級 GPU** 上——資源受限也可行。」

關鍵數字（挑 2–3 個講）：
- 繁中對話微調：F1 0.19 → 0.35（資料量 5k→30k 持續提升、未飽和）
- 語境貢獻：+0.151（乾淨 2×2 消融）
- 單張 RTX 4070、LoRA adapter 僅 17MB

---

### ⑦ 收尾與願景（20 秒）
> **旁白**：「Visual Mask System 讓純文字對話重新帶上情緒的溫度，降低誤解。目前個人化動態面具由生成層持續完善，學習迴圈的閉環強化學習列為下一步。謝謝。」

## 🛟 出包備案

| 狀況 | 對策 |
|---|---|
| tunnel 斷線 / 網址變 | **一定要有錄影版備援**；現場失敗就切錄影 |
| 首則訊息很慢 | 上場前已暖機（見清單）；仍慢就先講開場旁白拖時間 |
| Breeze2 某句判讀不如預期 | 用**預演時確認過、固定下來的用詞**；並保留 `/debug` 端點當佐證（推理鏈仍正確） |
| 真面具未齊、出現色塊 | 誠實說「視覺面具由生成層產出、完善中」，重點放情緒判讀正確性 |
| 現場完全連不上 | 全程走錄影版 |

## 🎥 錄影 vs 現場

- **建議以錄影為主**：競賽 demo 最忌臨場翻車。錄一段乾淨的（LINE 畫面 + 旁白 + debug 端點切換），失誤可重錄。
- **現場加分**：若允許現場互動，可請評審出一句話，即時判讀——但**務必有錄影備援**。
- 錄影建議同時錄「LINE 手機畫面」和「電腦上的 debug 端點」，剪接對照，最能展現『看起來簡單、背後在推理』。
